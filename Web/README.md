# Свет · Web

Исходный код: [andreykeks/setcarlight](https://github.com/andreykeks/setcarlight).

Статическое приложение на HTML, CSS и JavaScript для расчёта разметки стены при регулировке фар. Все размеры — в миллиметрах. Расчёты выполняются в браузере, параметры и список подготовки сохраняются в localStorage. Серверная часть, база данных и переменные окружения для работы сайта не нужны.

Проект подготовлен к Vercel, но ещё не опубликован. Целевой адрес — **https://setcarlight.vercel.app**, если имя доступно при создании проекта.

## Локальный запуск

Из корня репозитория:

```sh
npm --prefix Web run preview
```

Откройте http://127.0.0.1:4173. Сервер раздаёт только `Web/public`, то есть те же файлы, которые будет публиковать Vercel. Для локального сервера нужен Python 3; Node.js 22.x нужен для проверок. Версия Node закреплена в `package.json` и `.nvmrc`.

## Подготовка выпуска

```sh
npm --prefix Web run build
```

Команда проверяет синтаксис JavaScript и запускает 19 тестов, в том числе 77 эталонных расчётных сценариев. При ошибке выпуск прерывается. Готовые HTML/CSS/JavaScript уже находятся в `public`; транспиляция, упаковка и установка зависимостей не требуются. `npm install` перед проверками выполнять не нужно.

Можно запускать проверки отдельно:

```sh
npm --prefix Web run check
npm --prefix Web test
```

## Настройки Vercel

Импортируйте репозиторий из личного GitHub в личную команду Vercel. При создании проекта укажите:

| Настройка | Значение |
| --- | --- |
| Project Name | `setcarlight` |
| Root Directory | `Web` |
| Framework Preset | `Other` |
| Build Command | `npm run build` |
| Output Directory | `public` |
| Install Command | Пропустить установку — пустая строка в `vercel.json` |
| Node.js Version | `22.x` |
| Production Branch | `main` |
| Environment Variables | Не требуются |

`Root Directory` задаётся при импорте или в настройках проекта Vercel. Остальные параметры публикации описаны в `Web/vercel.json`; версия Node — в `Web/package.json`. Если Vercel определил проект иначе, проверьте прежде всего корневую папку `Web`.

Конфигурация задаёт:

- `framework: null` — статический сайт без фреймворка, режим Other.
- `outputDirectory: public` — тесты, документация и конфигурация не доступны посетителям.
- `buildCommand: npm run build` — обязательные проверки перед выпуском.
- `installCommand: ""` — шаг установки зависимостей пропускается.
- HTTP-заголовки CSP, `nosniff`, Referrer-Policy и Permissions-Policy.
- `Cache-Control: public, max-age=0, must-revalidate` — браузер перепроверяет файлы при обновлении, поскольку имена ресурсов не содержат хешей.

Навигация использует якоря `#calculator`, `#preparation`, `#guide`. Общее перенаправление всех адресов на `index.html` не требуется: неизвестные пути должны возвращать 404.

`.vercelignore` исключает локальные артефакты, документы и браузерные сценарии из загрузки через CLI; расчётные тесты остаются доступны шагу build. `.gitignore` исключает локальную привязку `.vercel`, секреты и служебные файлы сеанса из Git.

## Публикация и обновления

1. Разместите исходники в личном репозитории GitHub.
2. В Vercel выберите Add New → Project, импортируйте этот репозиторий и задайте настройки из таблицы.
3. Запустите Deploy. В журнале Build Logs должны успешно пройти проверки.
4. Откройте выданный адрес и проверьте калькулятор. В Settings → Domains проверьте назначение `setcarlight.vercel.app`; имя нельзя считать закреплённым до успешного назначения.

Собственный домен и настройки DNS не нужны. При сохранении стандартной Git-интеграции изменения в `main` выпускаются в Production; отдельные ветки и pull request получают Preview. Проверяйте изменения в Preview перед слиянием в `main`. История находится в Deployments; предыдущий выпуск можно вернуть через Instant Rollback.

При переходе со старого домена настройки localStorage автоматически не переносятся: браузер хранит их отдельно для каждого адреса.

Проект не использует загрузку Vercel Toolbar. CSP разрешает скрипты только с адреса сайта; если включить Toolbar в настройках Vercel, для него потребуется отдельно согласовать CSP по документации Vercel. Сам калькулятор работает без Toolbar.

## Браузерная проверка

`tests/browser.mjs` проверяет размеры 1440×1000 и 390×844: загрузку ресурсов, расчёты, схемы, валидацию, сохранение настроек, подготовку, навигацию и печатный PDF. Сценарий запускается локально или в CI и больше не зависит от Docker или plusap.

Playwright нужен только для этих дополнительных проверок; он не требуется для сборки Vercel и не входит в публикуемые файлы. В среде с установленными Playwright и Chromium:

```sh
cd Web
BASE_URL=http://127.0.0.1:4173 node tests/browser.mjs
```

Снимки и PDF сохраняются в `Web/artifacts`; путь можно изменить через `QA_ARTIFACT_DIR`. Для собственного исполняемого файла Chromium предусмотрен `CHROMIUM_EXECUTABLE_PATH`. После публикации проверка публичного Production-адреса запускается так:

```sh
cd Web
BASE_URL=https://setcarlight.vercel.app node tests/published-smoke.mjs
```

Она проверяет HTTPS-страницу, CSP, буфер обмена, сохранение настроек и недоступность служебных файлов. Защищённые Preview требуют доступа Vercel; сценарий рассчитан на общедоступный Production.

## Возможности

Отдельные высоты фар, боковая стена слева/справа, разворот по двум замерам от фар, угол стен по трём сторонам треугольника, привязка отметок к углу и поправка от стекла до линзы. Рабочий угол выбирается переключателем «По фарам / По треугольнику»; оба способа остаются доступны для сравнения.

На схеме у обеих фар СТГ имеет горизонтальный участок слева и подъём вправо от центра. Высота относится к левому горизонтальному участку; форма подъёма условная. Кнопка «Сохранить PDF» открывает диалог печати браузера. Расширенная геометрия начинается с новой страницы.
